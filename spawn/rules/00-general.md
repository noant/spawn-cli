# General (language-agnostic)

### Character set (code, logs, documentation, messages)
- No emojis or exotic Unicode in code, logs, documentation, or messages; use plain ASCII where practical.

### Questions first, edits second
- If the user only asked a question, answer first; do not edit files unless changes are clearly needed.
- When changes are needed after the answer, keep proposals minimal.

### Documentation, comments, and logs
- User-facing replies, documentation, and task descriptions: concise wording; minimal markdown (avoid decorative bold or italic); explain with lists and structure; short, clear sentences.
- Keep information concise in both chat and documentation, but do not omit important points when describing.
- Do not create or update documentation files (README, USAGE, etc.) unless explicitly requested.
- Write comments, documentation text, log messages, and any text inside code blocks only when explicitly requested.

### No automatic build/run; concise change recap
- Do not build, run, or "verify by compiling" after making changes unless the user explicitly asks for it.
- After code changes are made, summarize the final changes in chat very concisely (what changed and where), without extra narration.

### Language (chat, specs, and in-code text)
- Reply in Russian in chat.
- For spec text and other technical write-ups, use English.
- For comments, docs, logs, and in-code text you add: use English, even if the surrounding code is not.
